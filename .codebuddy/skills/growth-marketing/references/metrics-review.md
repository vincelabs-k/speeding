# Metrics Review — Retrospective Framework

> **基线快照：2026-08**。指标表述以「长期可持续 / 用户价值」为锚，不以短期收入数字为中心。

---

## 一、utm_source 渠道 ROI 分析

每个渠道的数据来自 `docs/utm-sources.md` 登记的 utm_source，逐渠道记录：

| 指标 | 定义 |
|---|---|
| 展示（Impressions） | 帖子被看到次数 |
| 点击（CTR） | 链接点击 / 展示 |
| 安装（Installs） | 到达落地页并完成安装 |
| 留存（Retention） | 安装后 7 天仍在使用 |
| 转化（Conversion） | 留存用户中发生目标行为（注册/付费/分享）的比例 |

**渠道 ROI = 转化用户数 / 投入时间成本**。高 ROI 渠道加权分配后续投入；低 ROI 渠道明确砍掉或换打法，
不因为"发帖容易"而继续。

## 二、安装 → 留存 → 转化漏斗

```
展示 → 点击 → 安装 → 激活（首次使用核心功能）→ 留存（7 天）→ 转化
```

- 每层列出转化率，定位瓶颈在哪一层：
  - 展示低 → 定位/标题问题（重写一句话定位）
  - 点击低 → 内容钩子问题
  - 安装低 → 落地页/商店页问题
  - 留存低 → 产品核心价值问题
- 高 ARPU 用户价值在于留存与转化层，不追求展示量的虚荣指标

## 三、高价值渠道加权决策

- 按 ROI 排序渠道，前 2 名加权分配 80% 后续投入
- 同一渠道内比较不同 utm placement（如 `x_pitch` vs `x_video`），收敛到有效 placement
- 决策以「长期可持续」为锚：SEO/Newsletter/集成等复利渠道权重高于一次性爆发渠道

## 四、分阶段透明度策略（数据披露边界）

| MRR 阶段 | 披露策略 | 说明 |
|---|---|---|
| $0-$10K | 完全透明（晒 Stripe/GA 截图） | 透明是唯一获客优势 |
| $10K-$30K | 选择性透明（删具体收入帖，只分享决策/团队故事/客户案例） | 竞品开始对标公开数据 |
| $30K+ | 极简公开（年度复盘 + 少量里程碑） | Build in Public, Grow in Private |

停止透明化三信号：已有稳定替代渠道；同类竞品对标你的公开数据；写内容变成"维护人设"。

## 五、Day 30 公开复盘帖结构

数据透明是 2026 差异化营销资产——公开复盘帖带来第二轮传播。结构：

```
1. 核心数字表（展示/点击/安装/留存/转化，配截图）
2. 分渠道拆解（每个 utm_source 的 ROI，诚实指出浪费）
3. 成功做法 2-3 条 + 失败做法 2-3 条
4. 数据说明的下一步决策（重写定位/换渠道/新功能）
5. 感谢社区 + 开放讨论问题
```

（具体模板见 `copywriting-templates.md` 第六节）

## 六、失败判定与第二轮

- **失败判定**：<1K 展示 / <5 试用 → 通常是定位问题，不是渠道问题
- **应对**：重写一句话定位，第 12 天发"第二轮"内容；不假装第一次没发生（诚实承认 = 社区加分）
- **迭代节奏**：每轮发布后按漏斗定位瓶颈，只改一个变量，不全面重来
