# Copywriting Templates — English Community Content Templates

> **基线快照：2026-08**。发布前到 `docs/utm-sources.md` 登记 `{CHANNEL}` 的 utm_source，
> 将 `{LINK}` 替换为带对应参数的实际链接。模板正文零付费提及（IH 模板除外）。
> 所有模板为英文产出，面向欧美英文社区。

占位符约定：`{PRODUCT}` 产品名、`{LINK}` 带 utm_source 的链接、`{CHANNEL}` 渠道 utm_source 名、
`{SCREENSHOT}` / `{DEMO_GIF}` 截图与录屏占位、`{NUMBER}` 数据占位。

---

## 一、万能软文结构（所有帖子/图文的地基）

**60/30/10**（帖子类）：60% 软性价值叙事 + 20% 技术 + 20% 创作

1. **场景痛点开头**（1-2 段）：具体到可代入的日常场景，不喊口号
2. **转折**：一次真实的发现/踩坑/转折点（第一人称）
3. **三点核心价值**：每条 = 场景 + 能力 + 结果
4. **诚实对比**：承认限制，说明为什么对目标人群仍值得一试
5. **"让我意外的事"**：一个反直觉观察（这是 upvote 关键点）
6. **具体反馈请求**：问具体问题，不要泛泛"求意见"
7. **链接注明免费**：`It's free to try, no account needed`（不写付费信息）

## 二、Show HN 模板（Hacker News）

**60/30/10**：30% 商务 + 50% 技术 + 20% 创作

**规则提示**：发帖前读 `newsguidelines.html` 与 `showhn.html`；禁求 upvote；发帖后立即发首条评论。

**标题**：`Show HN: {PRODUCT} – {一句：解决什么问题}`

**正文（三件事结构）**：
```
What it does: {一句话功能}
Why I built it: {个人故事/痛点，第一人称}
How it works: {技术要点 2-3 条，诚实说明架构选择与取舍}

{15 秒录屏占位：{DEMO_GIF} 或 {SCREENSHOT}}

Honest limitations: {诚实列出限制}

I'd love feedback on: {1-3 个具体问题，如 UI/性能/定价感知}

Try it free: {LINK} (no account required)
```

**首条评论模板**（发帖后立即发布）：
```
Hey HN — I built this because {1 句话动机}。The interesting part is {技术/设计上的一个亮点}。
Happy to answer questions about {架构/性能/隐私} here。
```

## 三、Reddit 帖子模板（灾难故事先导）

**60/30/10**：60% 软性价值叙事 + 20% 技术 + 20% 创作

**规则提示**：遵守 10% 自我推广规则；先确认目标 subreddit 版规与 karma 门槛；**灾难故事先导 > 产品 pitch**
（`r/freelanceUK` 产品先导被封 365 天 vs `r/ContractorUK` 故事先导被接受）；正文字数社区决定，不空泛。

```
{Title: 一个具体问题/失败/教训，而非产品名}

{第一段：具体场景 + 具体数字的痛点/失败故事，第一人称}

{第二段：转折——试了什么，什么有效（此时才自然引出 {PRODUCT}）}

{第三段：2-3 条具体收获 = 场景 + 能力 + 结果}

{诚实对比段：和默认体验/流行方案比，它好在哪、差在哪}

{反馈请求：具体问题，如"有没有人也遇到 xxx？你们怎么解决的？"}

{链接（如有）：{LINK}，注明 free to try}
```

**注意**：若 subreddit 版规禁止外链，正文给截图 `{SCREENSHOT}` 并将链接放评论区。

## 四、Indie Hackers 长帖模板（收入透明特例）

**60/30/10**：60% 软性价值叙事 + 20% 技术 + 20% 创作（含数据事实陈述）

**规则提示**：IH 文化推崇收入透明，但姿态是"分享故事"；被顶上去的长帖 = 数据截图 + 具体失败复盘，
不是进度汇报；冷启动先评论 10 篇长帖积累 profile 再发帖。

```
{Title: 结果/教训优先，如 "How {PRODUCT} went from 0 to {NUMBER} users in 30 days"}

{开场：1-2 句核心数字 + 一句"这篇文章讲什么"}

{背景：为什么做这个（个人故事）}

{数据截图：{SCREENSHOT}（MRR/用户数/留存，配一句话趋势说明）—— 2026 年被顶上去的关键要素}

{失败复盘：至少 1 个具体失败 + 学到了什么（分享失败比分享成功多 3-5 倍互动量）}

{具体做法：渠道、定价、分发中的 2-3 个可复用决策}

{下一步计划 + 具体反馈请求}

{链接（可选）：{LINK}}
```

## 五、X 推文模板（文章链接 + 摘要推）

**60/30/10**：50% 商务 + 20% 技术 + 30% 创作

**规则提示**：2026 算法转向文章链接（"everything platform"）——「文章链接 + 摘要推」组合触达率
有时高过 7 条 Thread；**不写 "Follow for more"**（已降权）；发布后 30 分钟内逐条回复评论（首波法则）。

**模板 A（产品发布，Day 0）**：
```
{一句痛点/结果 + 15 秒录屏 {DEMO_GIF}}

I spent the last {N} weeks building {PRODUCT} — {一句话定位}。

{摘要推 2-3 行：核心亮点 = 场景 + 能力 + 结果}

Try it free: {LINK}
```

**模板 B（数据透明，周一固定）**：
```
{MRR/用户数截图 {SCREENSHOT}} + {一句话趋势}

{这条数据说明什么：1 个反直觉观察/学到的东西}

{Hook 问题，引导回复}
```

**模板 C（失败/教训，周三）**：
```
I spent 3 days building a feature nobody wanted。Here's what I learned:

{1 个具体教训 + 数据或细节}

{开放问题}
```

## 六、Day 30 公开复盘帖模板（数据透明二次传播）

**用途**：发布 30 天后把数据公开，作为第二轮传播资产；在数据透明本身就是营销的 2026，
这是差异化优势。可发往 IH / Dev.to / X 长推 / 个人 blog。

```
{Title: "30 days after launch — here's the data" 风格}

{核心数字表：展示/点击/安装/留存/转化，配 {SCREENSHOT}}

{分渠道拆解：每个 utm_source 的 ROI，诚实指出哪个渠道浪费了时间}

{成功做法 2-3 条 + 失败做法 2-3 条}

{数据说明的下一步决策（重写定位/换渠道/新功能）}

{感谢社区 + 开放讨论问题}
```

---

## 七、模板通用规则

1. **正文零付费**：除 IH 模板外，正文不出现 price/pay/paid；需要时写 `free`、`no credit card required`
2. **链接统一**：全部指向 `{LINK}`（带 utm_source），发布前完成 `docs/utm-sources.md` 登记
3. **15 秒录屏必附**：Day 0 发布推文/帖子必须附 `{DEMO_GIF}` 或 `{SCREENSHOT}`
4. **诚实的限制**：每篇正文保留一句限制说明，这是社区信任的来源
5. **不群发**：同一内容 48 小时内不原样发 5 个渠道；每渠道按各自模板改写
